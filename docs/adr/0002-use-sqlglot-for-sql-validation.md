# ADR 0002: 使用 sqlglot 进行 SQL 校验

## 状态

已采纳

## 背景

平台需要在用户提交 SQL 前对其进行校验：识别所引用的表、确认表名在白名单内、并阻断危险写法。原方案基于 `sqlparse` 实现，仅对 SQL 做词法切分与 token 重组。

在实际使用中暴露出以下问题：

- **无法追踪 WITH 别名**：`sqlparse` 不构建 AST，遇到 `WITH t AS (...) SELECT ... FROM t` 时，会把 CTE 别名 `t` 误当作物理表，导致白名单校验误报。
- **表引用识别不准**：子查询、JOIN、别名等结构下的表引用难以精确提取，存在漏判与误判。
- **难以做语义级校验**：例如禁止 `SELECT *`、强制带 `LIMIT`、限定可聚合列等需求，在 token 层面难以稳定实现。
- **gold SQL 对齐困难**：评测框架的 gold SQL 与用户 SQL 需要同一套规范化与校验逻辑，原方案无法满足。

团队对比了 `sqlparse`、`sqlglot`、`mo-sql-parsing` 等方案，需要一个能生成稳定 AST、支持多方言、且社区活跃的库。

## 决策

采用 **sqlglot** 替代 sqlparse 进行 SQL AST 校验。

具体要点：

- 使用 `sqlglot.parse_one(sql, dialect=...)` 将 SQL 解析为 AST，统一方言处理。
- 遍历 AST 精确提取表引用（含 CTE 定义与引用），先解析 `WITH` 子句建立别名表，再对 `FROM`/`JOIN` 中的引用按别名优先解析，物理表才进入白名单校验。
- 基于 AST 实现语义级校验：禁止 `SELECT *`、强制聚合查询带 `LIMIT`、限定可访问列等。
- gold SQL 与用户 SQL 走同一套解析与校验路径，保证评测口径一致。

## 结果

- **正面**：WITH 别名与表引用识别准确，白名单校验误报显著下降；语义级校验可在 AST 上稳定实现，覆盖 token 层面无法表达的规则。
- **负面**：引入对 sqlglot 版本的依赖，AST 结构在主版本间可能调整。
- **限制**：将 sqlglot 依赖锁定在 `<26.0`，避免上游破坏性变更影响校验逻辑；gold SQL 需与用户 SQL 同步校验，新增表/字段时需同时更新 gold 用例。
- **后续**：旧 sqlparse 校验路径在迁移完成后下线，所有 SQL 校验入口统一走 sqlglot。
