# ADR 0001: 使用 LangGraph 进行 Agent 编排

## 状态

已采纳

## 背景

平台原有的 Agent 编排基于硬编码状态机实现：节点跳转通过 `if/else` 分支与全局状态变量串联，新能力接入需要修改编排主流程代码，且每一步只能串行执行。

随着 Agent 能力数量增长，原方案暴露出明显的扩展性问题：

- **扩展性差**：新增一个节点需要改动编排主流程，并手工维护状态迁移表，容易遗漏边界条件。
- **难以并行**：部分相互独立的子任务（如多源数据查询）只能串行执行，端到端延迟随节点数线性增长。
- **难以调试**：状态散落在多处，缺乏统一的 checkpoint 机制，出错后难以从中间步骤恢复或回放。
- **难以复用**：节点逻辑与编排逻辑耦合，无法在不同编排流中复用同一节点。

团队评估了若干编排方案（手写状态机、LangChain LCEL、LangGraph StateGraph、自研 DAG 引擎），需要选择一个既能表达条件分支与并行、又能提供执行持久化的方案。

## 决策

采用 **LangGraph StateGraph** 替代硬编码状态机进行 Agent 编排。

具体要点：

- 使用 `StateGraph` 描述节点与迁移关系，节点间通过共享 State 对象传递数据，状态结构显式声明。
- 利用 LangGraph 的 **条件分支**（conditional edges）表达基于中间结果的分流，替代手写 `if/else`。
- 利用 **并行节点** 让相互独立的子任务并发执行，缩短单轮编排耗时。
- 启用 **checkpoint** 机制持久化中间状态，支持出错重试与人中途回放。
- 节点逻辑以纯函数形式实现，与编排拓扑解耦，便于在不同编排流中复用。

## 结果

- **正面**：新能力接入只需声明节点与边，不再改动编排主流程；并行节点使独立子任务耗时收敛到最长一支；checkpoint 提供了可观测与可恢复能力。
- **负面**：团队需要学习 StateGraph 的编程模型与状态合并语义，存在一定学习成本。
- **限制**：LangGraph 单步执行（一次 `invoke` 推进一个节点）的能力受运行时支持约束，已在运行手册中文档化，复杂交互场景需通过外部循环驱动。
- **后续**：旧硬编码状态机的迁移按能力逐步进行，迁移完成后将下线旧编排代码。
