### 通读发现的实际问题（已核验）

1. `monitoring/grafana/dashboards/ops-platform.json` 仅 5 字节残缺，三个 compose 均无 grafana 服务 → Grafana 环缺失。
2. `docker-compose.monitoring.yml:28` 用 `prom/prometheus:v0.27.0`（不存在的 tag，v0.27.0 是 Alertmanager 版本）→ 拉镜像必失败。
3. `Makefile:67 run-prod` 用 `wsgi:app`，但仓库无 `wsgi.py`（Dockerfile 用 `app:app`）。
4. `cd.yml` 蓝绿部署引用 `ops_backend` / `ops_nginx`，与 compose 实际服务名 `web` / `nginx` 不符；previous.json 写入顺序错误导致回滚失效。
5. 迁移缺口：`erp_exchange_rate`/`erp_stock_take`/`erp_customer`/`erp_return_order` 无建表迁移，仅靠 dev 的 `db.create_all()` → 生产走 alembic 会缺表。
6. `models/__init__.py` 未导出 bom.py / finance.py 的 6 个模型，靠 routes/services 顶层 import 间接注册。
7. `services/db_router.py` 的读写分离为**占位未真正启用**。
8. 前端 `switchTab()` 从不更新 `aria-selected`；CSS 定义了 modal 焦点陷阱但 app.js 中 `modal` 出现 0 次。
9. `schemas.py` 定义 11 个 Marshmallow Schema，实际只有 3 处调用 `.validate()`；flask-smorest 未接入路由层。
10. README 落后：finance（6 端点）、mrp（5 端点）、MFA（2）、`/api/dashboard`、fde backfill/run-dq、loop reset 等均未收录；部分权限点标注与代码不符（returns 实为 `return:write`、transfers 实为 `transfer:write`、auth/me 实为仅认证）。
